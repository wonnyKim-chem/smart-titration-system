# Smart Titration Curve Analysis System

두 모바일 카메라에서 뷰렛 부피와 pH 계측기 표시값을 읽고, 시간 기준으로 결합해 적정 곡선과 당량점을 실시간 분석하는 FastAPI 웹 시스템입니다.

## 구성

```text
.
├─ launcher.py              PySide6 Windows 운영 패널과 서버 제어
├─ main.py                  FastAPI, WebSocket, 시간 정합, SciPy 분석
├─ certificate_manager.py   24시간 서버 인증서 발급과 자동 갱신
├─ wifi_share.py            Windows Wi-Fi 프로필과 초대 QR 생성
├─ static/
│  ├─ burette.html/js       뷰렛 원근 보정과 메니스커스 추적
│  ├─ ph-meter.html/js      pH·디지털 온도 다중 ROI OCR
│  ├─ indicator.html/js     흰 종이 보정 지시약 색 측정
│  ├─ dashboard.html/js     pH·온도·Δ색 Plotly 분석 화면
│  ├─ offline-store.js      IndexedDB 영구 큐
│  └─ reliable-socket.js    ACK 기반 재접속·배치 동기화
├─ tests/test_main.py
├─ titration.spec
└─ build.ps1
```

## 개발 실행

Python 3.11 이상이 필요합니다.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python launcher.py
```

GUI가 HTTPS 인증서, 서버 상태, 접속 주소와 QR 코드, 연결된 카메라 수, 측정 레코드 수를 표시합니다. 인증서가 유효하면 서버가 자동으로 시작되며, 창을 닫아도 Windows 알림 영역에서 계속 실행됩니다. Windows 방화벽에서 TCP 8000 인바운드 연결을 허용해야 다른 기기가 접속할 수 있습니다.

개발 중 콘솔 서버만 실행하려면 인증서 설정 후 `python main.py`를 사용합니다.

| 경로 | 화면 |
| --- | --- |
| `/` | 실시간 분석 대시보드 |
| `/burette` | 뷰렛 카메라 |
| `/ph-meter` | pH 계측기 카메라 |

## 모바일 카메라와 HTTPS

모바일 브라우저의 `getUserMedia`는 신뢰된 보안 컨텍스트에서만 동작합니다. PC의 `localhost`는 HTTP 예외가 적용되지만, 휴대폰에서 `http://192.168.x.x:8000`처럼 접속하면 카메라 API가 제공되지 않습니다. iPhone의 Safari와 Chrome은 모두 iOS의 WebKit 카메라 계층을 사용하므로 두 브라우저에 동일하게 HTTPS가 필요합니다.

### 1. Windows에서 로컬 인증서 만들기

HTTPS는 서버 시작과 모바일 브라우저 카메라 사용에 필수입니다. 첫 EXE 실행만으로 인증서 설치나 Windows 보안 창이 자동 실행되지는 않습니다. GUI는 `HTTPS 필수 설정 미완료` 상태와 이유를 표시합니다. 사용자가 `HTTPS 필수 설정`을 누르고 설명을 확인한 뒤 동의해야 아래 스크립트가 실행됩니다. 수동으로 실행할 수도 있습니다.

```powershell
.\setup-ios-https.ps1
```

스크립트가 `mkcert`를 찾지 못하면 `winget`으로 자동 설치합니다. 인증서와 키는 한글 경로 문제를 피하기 위해 `%LOCALAPPDATA%\SmartTitration\certs`에 저장됩니다.

스크립트가 선택한 IP가 실제 Wi-Fi 주소와 다르면 다음처럼 직접 지정합니다.

```powershell
.\setup-ios-https.ps1 -IpAddress 192.168.0.28
```

Wi-Fi가 바뀌어 PC의 IP가 변경되면 새 IP로 인증서를 다시 만들어야 합니다.

앱이 실제 연결에 사용하는 **서버 인증서는 24시간만 유효**하며 만료 2시간 전 자동 갱신됩니다. 갱신 과정에서 HTTPS 서버가 자동 재시작될 수 있습니다. 모바일에 설치하는 로컬 CA는 장기 신뢰 인증서이므로 매일 다시 설치할 필요가 없습니다.

이 인증서는 카메라 접근 권한이나 인터넷 전송 권한을 부여하지 않습니다. 서버 PC와 모바일 브라우저 사이의 로컬 HTTPS 통신을 암호화하고, 접속한 서버가 이 PC인지 확인하는 용도입니다. 로컬 CA 개인키는 서버 PC의 `%LOCALAPPDATA%\mkcert`에만 보관해야 합니다.

로컬 IP에서 브라우저 카메라를 사용하려면 카메라를 사용할 각 모바일 기기에 `SmartTitration-RootCA.crt`를 한 번 설치하고 신뢰해야 합니다. 이 단계를 몰래 또는 자동으로 수행하지 않습니다.

### 2. iPhone에서 인증기관 신뢰하기

1. 스크립트가 출력한 `SmartTitration-RootCA.crt` 파일을 AirDrop, iCloud Drive 또는 이메일로 iPhone에 전송합니다. 개인키인 `rootCA-key.pem`은 절대로 전송하지 않습니다.
2. iPhone에서 `SmartTitration-RootCA.crt`를 열고 프로파일 다운로드를 허용합니다.
3. `설정 > 일반 > VPN 및 기기 관리 > 다운로드된 프로파일`에서 프로파일을 설치합니다.
4. `설정 > 일반 > 정보 > 인증서 신뢰 설정`에서 설치한 mkcert 인증서의 `완전 신뢰`를 켭니다.

### 3. HTTPS 서버 실행하기

EXE는 `%LOCALAPPDATA%\SmartTitration\certs`의 인증서를 자동으로 찾으므로 환경변수 없이 실행합니다.

```powershell
.\dist\SmartTitration\SmartTitration.exe
```

GUI의 모바일 접속 주소와 QR 코드는 실제 HTTPS 서버가 시작된 뒤에만 표시됩니다. 주소가 반드시 `https://`로 시작하는지 확인합니다. iPhone과 PC는 같은 Wi-Fi에 연결되어 있어야 하며, Windows 방화벽에서 TCP 8000과 iPhone의 해당 브라우저에 대한 `로컬 네트워크` 접근을 허용해야 합니다.

`대시보드 열기`는 서버 PC의 기본 브라우저에서 같은 실시간 데이터 화면을 엽니다. 창의 닫기 버튼은 서버를 종료하지 않고 알림 영역으로 최소화하며, 서버를 완전히 종료하려면 트레이 메뉴의 `서버 종료`를 선택합니다.

### 4. iPhone 권한 확인하기

- Safari: `설정 > 앱 > Safari > 카메라`를 `묻기` 또는 `허용`으로 설정합니다. 사이트를 연 뒤 주소 막대의 페이지 메뉴에서 해당 웹사이트의 카메라 권한도 허용합니다.
- Chrome: `설정 > 개인정보 보호 및 보안 > 카메라`에서 Chrome을 허용하고, `설정 > 앱 > Chrome > 로컬 네트워크`도 켭니다.
- 이전에 거부했다면 브라우저 탭을 닫고 다시 열거나 해당 사이트의 웹사이트 데이터를 삭제한 뒤 다시 허용합니다.
- Safari와 Chrome의 권한은 앱별로 관리되므로 한쪽에서 허용해도 다른 쪽에는 자동 적용되지 않습니다.

카메라 시작 후 iPhone 상단에 녹색 카메라 사용 표시가 나타나야 합니다. 녹색 표시가 없으면 HTTPS 또는 권한 문제이고, 녹색 표시는 있지만 화면이 멈추면 다른 카메라 앱을 종료한 뒤 페이지를 새로고침합니다.

### 5. Android 설정과 호환성

Android Chrome과 Samsung Internet에서도 카메라, IndexedDB, WebSocket, OpenCV.js 및 기기 방향 이벤트를 사용할 수 있습니다. Android에서도 카메라 API는 신뢰된 HTTPS 연결이 필요합니다.

1. `SmartTitration-RootCA.crt`를 Android 기기로 전송합니다.
2. Pixel 계열은 `설정 > 보안 및 개인정보 보호 > 보안 설정 더보기 > 암호화 및 사용자 인증 정보 > 인증서 설치 > CA 인증서`에서 설치합니다. Samsung 등 다른 제조사는 설정 검색에서 `CA 인증서` 또는 `인증서 설치`를 찾습니다.
3. Chrome 또는 Samsung Internet에서 HTTPS 주소를 엽니다.
4. 사이트의 카메라 권한을 `허용`합니다.
5. Android 12 이상에서 브라우저 앱의 카메라 권한과 시스템의 `카메라 액세스` 빠른 설정이 모두 켜져 있는지 확인합니다.

Android Chrome에서는 iOS의 `DeviceOrientationEvent.requestPermission()` 방식 대신 방향 이벤트를 직접 구독합니다. 현재 클라이언트는 두 방식을 분기 처리하므로 별도 코드 변경이 필요하지 않습니다. 카메라 조건은 강제값이 아닌 `ideal` 값으로 지정되어 있어 960×540 또는 15 FPS를 정확히 지원하지 않는 기기도 브라우저가 가능한 값으로 조정합니다.

공용 또는 관리형 학교 기기는 사용자 CA 설치가 정책으로 차단될 수 있습니다. 이 경우 학교 IT 관리자가 CA를 배포하거나, 추후 공인 도메인과 공인 인증서를 사용하는 구성이 필요합니다.

OpenCV.js, Plotly.js, Lucide 및 웹 글꼴은 CDN에서 불러옵니다. 인터넷이 차단된 실험망에서는 해당 파일을 `static/vendor`에 내려받고 HTML의 스크립트·글꼴 주소를 로컬 경로로 바꿔야 합니다. 측정 레코드는 네트워크 상태와 무관하게 IndexedDB에 먼저 기록되며, 연결 복구 시 200개 단위로 서버에 재전송됩니다.

## 보정과 판독

1. 뷰렛 카메라를 시작하고 화면 안내에 따라 메니스커스와 눈금 숫자가 함께 보이도록 맞춥니다.
2. 메니스커스가 안정적으로 인식되면 팝업에 현재 실제 부피를 입력합니다.
3. 적정용액을 3~5 mL 정도 배출하고 콕을 잠그면 두 번째 부피 입력 팝업이 나타나며, 입력 후 보정이 완료됩니다.
4. pH 카메라를 시작하고 LCD 숫자 화면의 중앙을 한 번 터치합니다. 앱이 화면형 윤곽, 밝기 임계값과 숫자 명암을 자동으로 선택합니다.
5. 인식이 잘 안 될 때만 접이식 보조 설정을 엽니다. 뷰렛은 일반적으로 `Canny 윤곽선`을 사용하고, 반사광으로 선이 자주 끊기면서 액체와 배경의 밝기 차이가 클 때 `밝기 이진화`를 사용합니다.

## 카메라 이동과 영상 녹화

- pH 클라이언트는 선택한 LCD 주변을 주기적으로 다시 탐색해 작은 카메라 이동을 따라갑니다. 밝기 변화에는 Otsu 자동 임계값을 사용하며, 저조도·과노출·흐림 또는 낮은 OCR 신뢰도가 감지되면 잘못된 값을 보내지 않고 자동 재탐색합니다.
- 뷰렛 클라이언트는 첫 번째 보정 시 눈금 패턴을 기준 템플릿으로 저장합니다. 이후 작은 상하 이동은 템플릿 매칭으로 보정하며, 큰 이동이나 순간적인 메니스커스 튐이 발생하면 측정을 일시 보류하고 화면을 다시 맞추도록 안내합니다.
- 카메라 원본은 가능한 경우 1280×720, 15 FPS를 사용합니다. `녹화 시작`과 `정지`를 누른 뒤 완성된 파일을 모바일 기기에 다운로드하거나 서버로 전송할 수 있습니다.
- 서버에 전송한 녹화는 `%LOCALAPPDATA%\SmartTitration\recordings`에 저장됩니다. 업로드 제한은 파일당 1.5 GB이며 WebM과 MP4를 지원합니다.
- 녹화 파일은 브라우저 메모리에서 완성되므로 매우 긴 실험은 20~30분 단위로 나누어 녹화하는 것을 권장합니다. 녹화 중에도 측정값은 기존 IndexedDB와 WebSocket 경로로 독립적으로 기록됩니다.

## 다중 클라이언트, 온도와 지시약 색

- 같은 채널에 여러 모바일 기기가 연결되면 0.5초 구간마다 각 기기 내부 평균을 먼저 계산하고, 기기별 평균을 동일 가중치로 다시 평균합니다. 전송 빈도가 빠른 기기가 결과를 지배하지 않습니다. 부피 0.15 mL, pH 0.15, 온도 1.0 °C보다 기기 간 차이가 크면 대시보드에 센서 불일치 경고가 표시됩니다.
- pH·온도 카메라에서 계측기 영역을 터치한 뒤 `pH 값`, `디지털 온도`, `아날로그 온도계` 중 유형을 선택합니다. pH 없이 온도만 측정하거나 한 화면에서 pH와 온도를 함께 측정할 수 있습니다. 디지털 온도를 계속 읽지 못하면 아날로그 보정 전환을 제안합니다.
- 아날로그 온도계는 서로 떨어진 두 눈금 위치를 화면에서 터치하고 각각의 실제 온도를 입력해 2점 보정합니다. 보정 후 액주 끝 위치를 온도로 환산해 별도 WebSocket 채널로 기록합니다.
- 대시보드는 온도-시간 그래프를 만들지 않습니다. 온도-부피 곡선과 평활화된 온도 최고점의 부피·온도를 표시합니다.
- 지시약 색 카메라는 플라스크 아래 무광 흰 종이를 자동 화이트 기준으로 사용합니다. 중앙 소용돌이, 하단 교반자석, 강한 반사광과 어두운 탐침 픽셀을 제외하고 RGB/HSL/Lab 중앙값과 `Δ색`을 기록합니다.
- 색 종말점은 Δ색-부피 곡선의 변화율이 가장 큰 지점입니다. pH 당량점과 함께 대시보드에서 비교할 수 있습니다.
- pH/ORP 전극 없이 색만 사용하는 경우 같은 지시약 농도와 조명에서 계산 당량점 또는 전극을 사용한 기준 실험으로 종말점 색·부피를 먼저 보정해야 합니다. 절대 pH/ORP가 필요하면 알려진 표준용액을 최소 두 개 이상 촬영해 별도 보정 곡선을 만들어야 합니다.
- 아날로그 액주 검출은 중앙 액주가 눈금과 함께 선명하게 보이는 온도계를 대상으로 합니다. 제품별 액주 색과 반사 특성이 다르므로 실제 장비에서 보정 후 검출 상태를 확인해야 하며, 액주를 찾지 못하면 값을 전송하지 않습니다.

## Wi-Fi 초대 QR

GUI의 `Wi-Fi 초대`는 Windows에 저장된 개인 Wi-Fi 프로필로 연결 QR을 만듭니다. 버튼을 누르고 경고에 동의한 경우에만 임시 XML에서 암호를 읽으며, 암호를 화면 텍스트·로그·설정 파일에 저장하지 않습니다. 학교 Enterprise Wi-Fi나 웹 로그인형 네트워크는 암호 QR 방식으로 초대할 수 없습니다.
